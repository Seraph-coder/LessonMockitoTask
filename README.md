# Пример использования Mockito

Смотрите тест [CustomerServiceTest](src/test/java/customer/CustomerServiceTest.java), там пример тестирования сервиса CustomerService.

## Задание

Протестировать сервис [ShoppingService](src/main/java/shopping/ShoppingService.java)

### Примечание

* Делать изменения в основном коде запрещено!
* У каждого теста должно быть описание о том, что именно вы тестируете
* Если вы считаете, что метод тестировать не надо, то тест всё равно создайте (с пустым телом метода), но в комментариях опишите почему вы считаете, что его тестировать не нужно.
* Не обязательно все тесты должны проходить, например, если вы нашли ошибку - тест обязан падать.

## Дополнительное задание

(_без выполнения этого задания оценку "отлично" не получить_)

Найти все логические ошибки

Найденные ошибки:
1) В текущей реализации установлено отношение «покупатель принадлежит корзине», в то время как должно быть наоборот — корзина должна принадлежать покупателю.

2) В текущей реализации невозможно изменить владельца корзины, хотя корректная бизнес-логика должна это предусматривать.

3) Корзина не очищается после покупки, из-за чего товары остаются в корзине, будто покупатель оплатил их и ушёл, не забрав.

4) Метод validateCount неправильно определяет допустимое количество: он запрещает добавить ровно оставшееся количество товара.

5) Метод get у ShoppingService при повторном вызове тем же с тем же пользователем выдает новую корзину, хотя у пользователя должна быть только одна корзина.

6) Метод edit не реагирует на отсутствие товара в корзине: в текущем виде он тихо игнорирует ситуацию, хотя должен бросать исключение.

7) В методе validateCount отсутствует проверка на null для product, что может привести к NullPointerException.

8) Во всех методах корзины, принимающих количество товара, отсутствует проверка на отрицательное число. Это приводит к неправильному и некорректному поведению.

9) В методе validateCanBuy переменная count (Integer) не проверяется на null, но позже сравнивается с int (product.getCount), что может привести к NullPointerException.

10) Метод buy обновляет остатки товаров и сохраняет их без транзакционной защиты. Отсутствие @Transactional может привести к неконсистентному состоянию данных при ошибках в середине процесса.

11) В методе buy отсутствует обработка ошибок при вызове productDAO.save, что также может привести к частично сохранённым данным.

12) Метод validateCanBuy не указывает доступное количество товара в сообщении об ошибке, что затрудняет понимание причины ошибки пользователем.

13) В системе отсутствует корректная валидация номера телефона покупателя: поле phone может быть null, пустым или содержать только пробелы, что приводит к некорректным данным.

14) Метод addCustomer выбрасывает общую ошибку вместо конкретных исключений, из-за чего сложно корректно обрабатывать ошибки на уровне контроллера или сервиса.

15) В методе getCart отсутствует проверка на null для customer, что приводит к потенциальному NullPointerException при передаче null.

16) Метод getProductByName не проверяет входной параметр name на null или пустую строку, что может приводить к некорректной работе DAO или неочевидным ошибкам.
